# The Response Game — Brand System v14

## Brand hierarchy

**Master brand:** The Response Game  
**Game mode:** Resource Run  
**Descriptor:** Incident Management Simulation

The acronym **TRG** is used as a clean wordmark. It is intentionally not a recreation of The Response Group corporate logo and does not use the rejected red-slash treatment.

## Brand promise

**Run the incident. Make the call. Watch what changes.**

The product should feel operational, credible, fast, consequential, and mature. It should never look like a slide deck, LMS, government portal, classroom game, clip-art exercise, or generic template dashboard.

## Visual language

### Core environment

- near-black / deep-navy operating environment;
- quiet blue-gray information surfaces;
- fine operational borders;
- restrained elevation rather than decorative card stacking;
- 11–16px corner radii, with compact instrument surfaces generally closer to 11–12px;
- no pill-box primary controls;
- no cartoon / clip-art resource movement.

### Semantic status colors

These meanings are fixed across every incident theme:

- **Green** — verified, deployed, healthy, on track
- **Amber** — current, watch, attention, process-in-progress
- **Red** — consequence, critical, late, degraded
- **Cyan / Blue** — information, situational awareness, command context

### Scenario identity colors

Incident-family accents are presentation-only and must never override semantic status meaning:

- Hurricane — atmospheric blue / indigo
- Wildfire — burn orange / ember
- Oil Spill — teal / recovery blue
- Chemical Release — muted lime / teal
- Refinery Incident — industrial orange / muted red
- Pipeline Incident — indigo / steel blue
- Maritime Incident — aqua / maritime blue
- Public Event — violet / command blue
- Severe Weather — slate blue / storm indigo
- Transportation Accident — response blue / caution amber

## Logo / wordmark

The TRG mark remains deliberately simple:

- white TRG letters;
- no red slash;
- no surrounding pill or badge;
- thin amber baseline as the master-brand accent;
- “THE RESPONSE GAME” written nearby when space allows.

`trg-mark.svg` remains the application / manifest mark.

## Typography

Primary family:

`Inter, system-ui, -apple-system, Segoe UI, sans-serif`

Hierarchy is created through scale, weight, tracking, and placement rather than novelty fonts.

- Landing display: approximately 56–100px responsive
- Mission title: approximately 40–68px
- Decision prompt: approximately 19–33px
- Command values: 9–18px depending on density
- Card / panel headings: 13–22px
- Body: 12–18px
- Operational labels: 6–11px uppercase with controlled tracking

## Operational iconography

Icons should resemble professional command-and-control symbology rather than illustration.

The v14 incident family set uses simple monochrome line icons for:

- hurricane;
- wildfire;
- oil spill;
- chemical release;
- refinery;
- pipeline;
- maritime;
- public event;
- severe weather;
- transportation incident.

Resource state is communicated with labels, lifecycle progress, status borders, counts, and timing — not a moving cartoon vehicle.

## Presentation standard

Every operational screen must answer three questions quickly:

1. **What is happening?**
2. **What needs my attention now?**
3. **What changed because of what I did?**

The persistent Command Status surface exists to answer the first question. Pending Work and the Decision Workspace answer the second. Operational Intelligence, resource lifecycle state, consequences, and period reviews answer the third.

If a visual element does not improve one of those answers, it should be removed or subordinated.

## AAR standard

After Action Review presentation should feel like the reporting side of the same incident-management platform:

- strong command header;
- incident / role / difficulty identity;
- KPI summary;
- objective status table;
- performance bars;
- strengths;
- improvement areas;
- recommended retraining;
- operational impacts;
- print-friendly layout.

The report may use a light body for printability, but the master-brand command header and hierarchy should remain visually continuous with the simulator.
