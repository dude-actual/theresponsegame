# Resource Run v14 RC1 — Before / After Comparison

| Area | v13 RC1 | v14 RC1 |
|---|---|---|
| Overall product feel | Mission-first serious game | Professional incident-management simulator |
| Command picture | Metrics distributed across header, map footer, and rail | Persistent unified Command Status instrument panel |
| Incident identity | Shared dark environment with limited per-hazard visual distinction | Ten restrained incident-specific visual themes and icons |
| Resource visualization | Generic vehicle-style map tokens | Operational resource markers plus lifecycle status cards |
| Request process | Primarily visible through decision prompts | Explicit seven-stage progress visualization tied to engine state |
| Queue | Name, priority, due time | Priority chip, destination/context, time-to-needed / lateness |
| Inventory | Available, committed, deployed text | Same data plus utilization state and out-of-service visibility |
| Map / COP | Stylized operational map | Scenario-aware situation canvas with condition context and non-cartographic status markers |
| Metric duplication | Incident dashboard card plus other metric areas | Dashboard duplication removed; persistent command band is authoritative presentation |
| Scenario differentiation | Content changes by hazard, visuals mostly shared | Content remains unchanged; visual identity changes with incident family |
| Mobile | Responsive simulator with bottom command dock | Same command dock plus dense persistent command status and reduced secondary detail |
| AAR download | Functional but visually separate light report | Professional command-style printable report consistent with simulator hierarchy |
| Visual geometry | More rounded “game card” treatment | Tighter radii, quiet borders, denser operations-software geometry |
| Status communication | Strong color system | Same semantic color logic plus explicit chips, labels, and lifecycle states |
| Mechanics | v12 simulation engine | Unchanged v12 simulation engine |
| Scoring / XP / retention | v12/v13 systems | Unchanged |

## What was intentionally removed or subordinated

- generic moving/vehicle visual language as the primary resource-status metaphor;
- redundant Incident Dashboard card in the desktop rail;
- oversized decorative surfaces where a status instrument communicates better;
- scenario-neutral presentation when incident identity can be conveyed without changing semantics.

## What was intentionally preserved

- mission briefing and contextual onboarding;
- Operational Intelligence feed;
- IMH job aid;
- keyboard shortcuts;
- period review;
- results, progression, retention, leaderboards, reports;
- all incident and role mechanics;
- all scoring weights and consequence behavior;
- local-first architecture.
